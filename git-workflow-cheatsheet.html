0) Pre‑flight (once per repo)

cd /path/to/your/repo
git status
git branch                 # confirm current branch (assume: main)
git remote -v              # confirm "origin" points to GitHub
Tip: If this branch hasn’t been pushed before, set its upstream once (see Set upstream).

1) Start work — always pull first

Keeps your local copy in sync with changes made on GitHub (including files added via the website).

git fetch origin
git pull --ff-only         # or: git pull --rebase (if you prefer linear history)
Why --ff-only? It updates only if your branch can fast‑forward (you’re behind with no local commits). If histories diverged, it stops safely so you can choose merge or rebase.

2) Edit files

git status
git diff                   # see unstaged changes

3) Stage changes

git add -p                 # interactively pick hunks
# or:
git add <file>
git add .

4) Commit

git commit -m "Explain the what and why"
# Need to tweak the last commit (not yet pushed)?
git commit --amend

5) Push

git push
# First time on a new branch:
git push -u origin <branch>

6) Before your next session

If you also add files on GitHub’s website, pull at the start of each work session:

git pull --ff-only         # or: git pull --rebase

Feature branches & Pull Requests

# create & switch to a feature branch
git switch -c feature/thing

# work → stage → commit
git add -p
git commit -m "Implement thing"

# publish the branch
git push -u origin feature/thing

# open a PR on GitHub (or with gh)
# after it’s merged:
git switch main
git pull --ff-only
git branch -d feature/thing
git push origin --delete feature/thing   # remove remote branch

If histories diverge

You have local commits and the remote has new commits. Choose one style:

A) Rebase (linear history)

git fetch origin
git rebase origin/main
# resolve conflicts → edit files → git add <fixed> → git rebase --continue
git push
# If this branch was already pushed before rebasing:
# git push --force-with-lease

B) Merge (simple, no history rewrite)

git fetch origin
git merge origin/main
# resolve conflicts → git add <fixed> → git commit
git push
Destructive option: If you intend to discard local commits and match remote exactly:
git fetch origin
git reset --hard origin/main

Handy checks

git log --oneline --graph --decorate --all   # visualize history
git status                                   # current state
git branch -vv                               # see tracking/upstream

Set upstream (first push)

git push -u origin main
# After this, future pushes/pulls can omit branch/remote.

Optional one‑time config (global)

# identity
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

# preferences
git config --global init.defaultBranch main
git config --global pull.rebase false      # or true if you prefer rebase
git config --global core.editor "nano"     # or "vim", etc.
SSH recommended: generate a key with
ssh-keygen -t ed25519 -C "you@example.com", add the public key to GitHub (Settings → SSH and GPG keys), then test with ssh -T git@github.com.
